动态规划最容易卡住的地方不是代码，而是状态定义。一旦状态没有描述清楚，转移方程就会变成猜公式，调试时也很难判断到底是边界错了还是遍历顺序错了。

我现在做 DP 题会先写下三个问题：

1. `dp[i]` 或 `dp[i][j]` 表示什么，是否能覆盖所有必要信息。
2. 最后答案从哪个状态取。
3. 当前状态依赖哪些已经计算过的状态。

## 以 0/1 背包为例

0/1 背包的核心限制是每个物品只能选一次。二维写法比较直观：

```cpp
for (int i = 1; i <= n; i++) {
    for (int j = 0; j <= capacity; j++) {
        dp[i][j] = dp[i - 1][j];
        if (j >= weight[i]) {
            dp[i][j] = max(dp[i][j], dp[i - 1][j - weight[i]] + value[i]);
        }
    }
}
```

这里 `dp[i][j]` 表示只考虑前 `i` 个物品、容量为 `j` 时的最大价值。转移分成“不选第 i 个”和“选第 i 个”。

如果压成一维，容量必须倒序枚举：

```cpp
for (int i = 1; i <= n; i++) {
    for (int j = capacity; j >= weight[i]; j--) {
        dp[j] = max(dp[j], dp[j - weight[i]] + value[i]);
    }
}
```

倒序的意义是避免同一个物品在本轮被重复使用。如果正序枚举，`dp[j - weight[i]]` 可能已经包含第 `i` 个物品，就变成完全背包。

## 状态设计的检查方法

我会用一个小样例手动推几格表，确认状态是否真的“无后效”。如果一个状态无法决定下一步，例如还需要知道某个选择是否已经发生过，就说明状态维度不够。

常见的补维方式：

- 位置维度：处理到第几个元素。
- 资源维度：剩余容量、次数、预算。
- 状态维度：是否持有、是否翻转、上一位是什么。
- 区间维度：当前处理的左右端点。

## 易错点

DP 的 bug 经常集中在边界和初始化：

- 最大值问题的非法状态不要初始化为 `0`，应该用一个足够小的负数。
- 最小值问题要注意不可达状态，避免拿 `INF + cost` 继续转移。
- 滚动数组更新时，要重新判断依赖方向。
- 区间 DP 通常先枚举长度，再枚举左端点。
